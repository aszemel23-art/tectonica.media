# TECTONICA

Русскоязычное издание об архитектуре и дизайне. Статический сайт на GitHub Pages, домен `tectonica.media`. Страницы содержат тексты и навигацию без JavaScript; JS нужен только для поиска и копирования ссылки.

## Редакция

Материалы и дата выпуска хранятся в `content.mjs`. Реестр кандидатов с результатами отбора — `editorial/`. Кредиты изображений находятся в материалах; адреса оригиналов — `assets/images/provenance.json`. Старый выпуск сохранён в `archive/legacy/`; старые якорные ссылки перенаправляются туда.

Для каждого выпуска сначала собрать 20–40 кандидатов из разных стран и рубрик. Проверить первоисточники, даты события и публикации, статус проекта и точность изображения. Не использовать другой проект как фотографию новости. Не превращать маркетинговые характеристики в проверенные факты. Публиковать достойные истории: 1–2 главные, 6–10 подробных материалов, короткая лента, продукты и выставки. Резерв сохранять с причинами. Не удалять прежние статьи при следующем выпуске.

## Форматы и развитие выпуска

Главная начинается с фотографии построенного проекта. `/daily/` — маршрут на 15 минут, `/features/` — большие разборы, `/radar/` — наблюдения редакции с подтверждающими примерами и открытыми вопросами. Основная навигация содержит восемь рубрик; «Мебель и свет» объединяет два прежних потока. Адрес `/category/lighting/` сохранён для старых ссылок.

Редакционные разборы хранятся в `editorial-features.mjs`. Они помечаются `analysis: true`, содержат несколько источников и ссылки на связанные статьи. Заголовки разделов задаются префиксом `## `. Новости сохраняются в `content.mjs`. В текущем реестре 35 исходных кандидатов и 5 редакционных тем; опубликованы 25 новостей/проектов и 5 авторских разборов/наблюдений.

Архивные страницы формируются по фактическим датам статей. Дата выпуска берётся из `edition`; `date` относится к конкретной публикации, `modified` при наличии — к её обновлению. RSS, индекс поиска и sitemap пересобираются из данных. Для следующего выпуска добавлять статьи, а не заменять массив прежними новостями. Дату на сайте не подменять текущими часами: она должна обозначать реально подготовленный выпуск.

### Проверка сборки

Node.js 20+: `npm run build`, затем `npm test`. Внешние пакеты для сборки не нужны. Генератор обновляет статьи, рубрики, архив, поиск, RSS, метаданные и sitemap. Готовые HTML-файлы коммитятся в репозиторий и обслуживаются существующим GitHub Pages. CNAME не менять.

Перед публикацией проверить главную, статью, поиск и рубрику на мобильном и настольном экранах. Проверить изображения, ссылки и кредиты. Автоматическая ежедневная публикация без редакционной проверки не включена.

## Если у новости нет фотографии

По запросу владельца издания создавать тематическую редакционную иллюстрацию встроенным ImageGen. Изображение должно раскрывать конкретную тему новости, не имитировать документальную фотографию, реальный продукт или экспонат. В карточках и статье явно обозначать «Иллюстрация TECTONICA» и использование ИИ. Сохранять промпт и происхождение в provenance.json. Фотографии существующих проектов сохранять.
